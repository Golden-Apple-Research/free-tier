# Languages — Translation & Register Skill

Translate technical documentation into a target language **without ever breaking the
content**: code stays functional, links stay byte-identical, structure stays intact.
Each target language has an **example/instruction file** in `examples/` that defines
its grammar, vocabulary, register, and hard rules.

**Before translating a single line into a language, read its example file completely.**
The example file is the single source of truth — it overrides any general instinct.

## Non-negotiable invariants (all languages)

1. **Markdown structure preserved exactly** — heading levels, tables, blockquotes,
   bold/italic, list indentation, frontmatter keys.
2. **Links byte-identical** — URL targets and relative `.md` paths never change.
   If a link's *text* must change, only the text inside `[…]` changes.
3. **Code blocks byte-identical except comments** — code must stay functional.
   Comments (`# …`, `// …`) and human-readable string values inside code MAY be
   translated. ASCII diagrams inside fences stay byte-identical (alignment!).
4. **Brand names and tech terms stay Latin** — AWS, Terraform, OAuth, UUID, API,
   CLI, MCP, GB, MAU, SKU names, product names.
5. **Frontmatter**: translate human-readable values (title, description); never
   rename keys; dates stay as-is (`August 2026`).
6. **Numbers**: follow the language file. Klingon converts quantities to number
   *words* (see `examples/klingon.md`); money, dates, versions, ports, HTTP codes,
   decimals, and SKU identifiers stay Arabic everywhere.
7. **No source-language residue** — a final scan must find zero words of the source
   language (German) in prose, headings, tables, and comments.

## Workflow (multi-pass, verified)

Scan simple → edit simple. Never one giant clever pass; several sequential passes
keep each diff reviewable and the PC load low (explicit project preference).

1. **Survey** — where does generated content come from? Translate the *canonical
   source tree* (e.g. `content/tlh/`), never the generated copy (docs-site sync
   wipes it: `docs-site/src/content/docs/` is regenerated by `sync-content.mjs`).
2. **Register pass** — read the language file, hand-rewrite 2–5 exemplar files,
   freeze the patterns, then batch the rest (subagents work well: exemplars +
   strict style guide + per-batch verification).
3. **Vocabulary pass** — scan for remaining translatable words; verify EVERY
   candidate against an attested source (dictionary/canon) before using it.
   See "Attestation discipline" below.
4. **Number/quantity pass** — convert quantities per language file rules.
5. **Verification pass** — run the recipes below; fix; re-run until clean.

## Enrichment registers (growth, not translation)

Some passes keep the language and grow the prose in a register: Hegelian
German (4–5× bytes), pirate anecdotes (~15–30%). The invariants tighten,
not loosen:

1. **Capture a baseline before the first edit** — per file: link set,
   code-fence MD5s, numeric-token Counter, and (for table-heavy files) the
   literal table rows. The un-synced copy under `docs-site/src/content/docs/`
   is the pre-edit witness until the next sync.
2. **Growth is strictly additive** — every original sentence survives
   byte-identically; new prose never rewrites, reorders, or "improves" it.
3. **New prose avoids new numeric tokens** — spell numbers as words
   (German number words, pirate "three moons") so the baseline Counter only
   ever sees original values.
4. **Byte-exact zones**: frontmatter, H1s, intro blockquotes, all table
   rows, code fences, link targets, quota/price/date cells, plan and
   service names. Philosophy/flavor goes *between* preserved elements.
5. **Closing conventions** per language file (Hegel: `## Vermittelte
   Verhältnisse` cross-link section, circular links welcome; sync-content
   rewrites relative `.md` paths to slug URLs — verify 0 broken links in
   `dist/` after build).
6. **Literal table-row check** is the only reliable guard against row
   duplication/mutation: every original `|`-line must occur verbatim in
   the new file. Run it fleet-wide at the end.

## Attestation discipline (constructed languages)

**Only attested vocabulary — never invent words.** Apparent patterns lie:

- `jonaS` looked plausible for "account" — attested nowhere; it was fabricated.
- `wutlh` is attested but means *underground* — not "active".
- `qey` is attested but means *in vain* — not "freeze".
- `QIH` means *destroy* — fine for `terraform destroy`, wrong for "deploy".
- `mIQ` means *roast/fry* — was wrongly used for "Gotchas".

Before introducing ANY new word: check TKD / KLI / klingonska.org canon /
tlhingan.org dictionary. Record the verdict (✅ with meaning, ❌ with correction)
in the language file's forbidden/verified lists so the mistake never returns.
If no attested word exists, use a loanword (see language file for the policy).

## Edit-call discipline

- One edit call per file. Combining edits for different files in one call fails
  atomically ("Could not find edits[N]") and applies nothing.
- For bulk word replacements prefer a scripted exact-match replace (python with
  count asserts) over sed — assert expected counts, report every mismatch.
- Group multi-word context edits; never blind-replace short tokens (`wa'`, `neH`)
  globally — they collide.

## Verification recipes

Run after every pass, on the canonical tree, then again on rendered output:

```
# 1) Source-language residue (German): umlauts + word list → expect 0
grep -rniE '[äöüÄÖÜß]|\b(und|oder|nicht|wird|werden|mit|für|auch|wenn|…)\b' content/tlh/ --include="*.md"

# 2) Forbidden/fabricated words → expect 0
grep -rn "jonaS\|wutlh\|\bqey\b\|mIQ" content/tlh/ --include="*.md"

# 3) Structure parity vs source tree: file count + heading count per file
# 4) Fallback banners in rendered HTML → expect 0
grep -rl "not yet translated" docs-site/dist/<locale>/

# 5) Rendered <main> content: strip theme UI strings, then umlaut scan → 0
# 6) Term counts for key vocabulary (should be > 0 and stable across builds)
```

Then `node scripts/sync-content.mjs && npx astro build` and re-run 4–6 on `dist/`.

## Rendering gotchas (Astro/Starlight sites)

- Smartypants converts ASCII `'` to typographic `’` and builds quote *pairs* from
  `'word'`-shaped sequences. In Klingon text (apostrophes are letters!) avoid
  doubled apostrophes: `wa''uy'` renders broken — use `wa'maH bIp` (10×100,000).
- Searches against rendered HTML must match the typographic `’`, not `'`.
- Theme UI strings (e.g. "Nächste Seite") appear in every locale equally — they are
  system-level chrome, not doc content; do not count them as residue.
